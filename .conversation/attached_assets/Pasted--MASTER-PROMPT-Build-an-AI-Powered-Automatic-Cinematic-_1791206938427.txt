# MASTER PROMPT — Build an AI-Powered Automatic Cinematic Story Video Creator

## 1. Your role and mission

Act as a senior full-stack developer, video-processing engineer, UI/UX designer, and software architect.

Build a complete, professional, production-quality web application that automatically transforms a user's local collection of photos, video clips, and MP3 music tracks into a beautiful, cinematic story video.

The application must be functional, not merely a prototype, mockup, landing page, or static UI demonstration.

The primary design principle is:

**Minimum user effort. Maximum cinematic impact.**

The user should be able to select a folder, choose three simple settings, click Generate, and receive a finished video with intelligently selected media, impressive visual effects, smooth transitions, and professionally mixed music.

Use your judgment to make sensible creative decisions automatically rather than asking the user to configure a complicated video editor.

## 2. First inspect the existing project

Before writing or modifying code:

1. Inspect the entire existing project structure, source files, package configuration, dependencies, scripts, Git status, and current architecture.
2. Determine whether this project already has a working application that must be preserved.
3. Identify the existing framework, build system, deployment environment, and technical limitations.
4. Write a concise implementation plan based on the actual project.
5. Reuse suitable existing components and dependencies wherever practical.
6. Do not replace working functionality, introduce an unnecessary framework migration, or overwrite unrelated files.

If the project is empty, choose a suitable modern architecture and explain the important technical decisions briefly.

Do not stop after producing a plan. Proceed with implementation and testing.

## 3. Core user experience

Create a polished, responsive application with an intuitive workflow.

### Step A — Select a local media folder

Allow users to select or import a local folder containing:

* Photographs: JPG, JPEG, PNG, WebP, and other supported image formats.
* Video clips: MP4, WebM, MOV, and other formats supported by the chosen processing pipeline.
* Music: MP3 and other explicitly supported audio formats.

Support desktop and laptop computers, including Windows and macOS.

Support mobile phones, including Android and iPhone, wherever the browser and operating system permit the necessary file access.

Use the best available browser APIs, such as the File System Access API where supported, and standard file-input or directory-upload fallbacks elsewhere.

On mobile, provide an intuitive way to select multiple photos, videos, and audio files through the system file picker. Do not assume that every mobile browser can grant access to an entire folder.

Important:

* Clearly communicate unsupported formats and permission limitations.
* Provide a reliable fallback when directory selection is unavailable.
* Process files selected by the user without requiring them to upload their personal media to a remote server.
* Never assume unrestricted access to a device's filesystem.
* Detect duplicate files where practical and avoid unnecessarily repeating the same media.

### Step B — Analyze the media automatically

After selection, inspect the media and display a beautiful preview gallery with thumbnails.

Automatically determine, where supported:

* Image dimensions and orientation.
* Video duration, resolution, and orientation.
* Available audio tracks and their durations.
* File readability and decoding errors.
* Approximate timestamps and ordering information when reliable metadata exists.

Generate a useful media inventory and determine how much usable content is available.

The application should adapt to small or large collections without requiring the user to arrange files manually.

If the folder contains insufficient footage or music for the requested duration, explain the limitation and offer sensible alternatives rather than silently creating a broken result.

### Step C — Let the user choose only the essential settings

The primary creation screen must emphasize these three settings.

**1. Final video duration**

Offer convenient presets, for example:

* 30 seconds
* 1 minute
* 2 minutes
* 3 minutes
* 5 minutes
* Custom duration

Allow custom durations within the application's technically supported limits.

**2. Video quality**

Offer clear choices:

* Standard — 720p
* High — 1080p
* Ultra — 4K, when supported by the device and processing pipeline

Clearly explain when a quality setting is unavailable or would exceed available memory, processing capacity, or other practical limits.

Do not upscale low-resolution source material and imply that it has gained genuine detail.

**3. Artistic mood**

Offer visually attractive mood presets with representative thumbnails and short descriptions.

Include at least:

* Cinematic — dramatic compositions, film-like color grading, elegant transitions.
* Romantic — warm tones, gentle movement, soft transitions, emotional pacing.
* Happy & Energetic — vibrant colors, lively cuts, upbeat rhythm.
* Travel Adventure — sweeping landscapes, dynamic motion, immersive pacing.
* Nostalgic — subdued colors, subtle film grain, gentle fades.
* Family & Memories — warm, natural colors and emotionally engaging pacing.
* Epic — dramatic imagery, bold compositions, impactful transitions.
* Minimal & Elegant — restrained effects, refined typography, clean transitions.
* Dreamy — soft visual treatments, smooth motion, atmospheric transitions.

Allow the application to add more moods later without redesigning the entire system.

Each mood must produce a meaningful difference in the finished video, not merely change the name or background color of the interface.

Use these three settings as the main workflow. Keep advanced controls optional and unobtrusive.

## 4. Automatic cinematic story generation

Implement a real story-generation pipeline that transforms the selected media into a coherent video.

### Intelligent media selection

* Automatically choose useful photos and video segments.
* Avoid repetitive sequences and excessive use of nearly identical images.
* Prefer visually interesting and technically usable content.
* Use available timestamps to establish a sensible chronological sequence when appropriate.
* Respect user expectations when dates or ordering are ambiguous.
* Balance photographs and video clips according to the collection's contents.
* Give important photographs appropriate screen time.
* Extract suitable segments from longer videos rather than always using entire clips.
* Avoid showing corrupted, blank, or unreadable media.
* Handle folders containing only photos, only videos, or a mixture of both.

### Cinematic movement and visual effects

Photos should not appear as a simple sequence of static slides.

Implement appropriate effects such as:

* Ken Burns-style zoom and pan.
* Smooth camera-like movement.
* Subtle parallax or depth effects when practical.
* Elegant fades and cross-dissolves.
* Carefully selected wipes and motion transitions.
* Slow motion where suitable and supported.
* Smooth transitions between portrait and landscape material.
* Color grading consistent with the selected artistic mood.
* Vignettes, subtle film grain, or other restrained effects when appropriate.
* Optional tasteful opening and closing sequences.

Avoid excessive transitions, random effects, distracting filters, and effects that make the application feel cheap.

Choose transitions according to the artistic mood and the visual relationship between adjacent scenes.

Maintain good image framing. Avoid stretching photographs or videos. Use appropriate cropping, letterboxing, or background treatments to preserve important subjects.

### Music and audio intelligence

Automatically discover usable music files in the selected collection.

The application should:

* Analyze music duration and supported audio metadata.
* Select and sequence tracks when several are available.
* Create smooth crossfades between tracks.
* Trim music to fit the target video duration.
* Avoid abrupt starts and endings.
* Apply appropriate audio fades.
* Balance music with original video audio.
* Reduce or duck music when original audio is important.
* Prevent clipping and excessively loud output.
* Avoid unnecessary silence between tracks.
* Prefer music that suits the selected artistic mood when meaningful information can be inferred.

Do not pretend to understand the emotional content of an audio file unless actual audio analysis supports that conclusion.

If no music is available, explain the situation and provide an appropriate alternative, such as generating the video without music or letting the user select another audio source.

Do not automatically use copyrighted external music or download music from the internet.

## 5. Automatic duration and timeline management

The exported video must match the requested duration as closely as the media and processing pipeline permit.

Create a timeline automatically by calculating:

* The number of scenes required.
* Appropriate duration for each photograph.
* Suitable in and out points for video clips.
* Transition overlap and timing.
* Music start, end, and crossfade points.
* Opening and closing sequences.
* Audio fade timing.

Ensure transitions are accounted for when calculating the total duration.

Prevent black gaps, accidental frozen frames, overlapping scenes that create incorrect timing, abrupt audio cuts, and unexpectedly shortened exports.

Use a deterministic timeline model so that preview and final rendering follow the same scene order, timing, and effects.

If an exact duration cannot be achieved because of technical or source-media constraints, report the actual result accurately.

## 6. Live preview and rendering progress

Before rendering, provide a useful preview of the planned story.

Include:

* Selected media thumbnails.
* Target duration and quality.
* Selected artistic mood.
* A timeline or scene sequence.
* A playable preview where technically feasible.
* A clear Generate Video action.

During generation, show meaningful progress stages, for example:

1. Analyzing media.
2. Building the story.
3. Preparing scenes.
4. Processing visual effects.
5. Mixing audio.
6. Encoding the final video.
7. Finalizing and validating the export.

Display a progress indicator, elapsed time, and useful status information.

Do not fabricate precise percentage completion when the rendering engine cannot provide it. Use stage-based or approximate progress where necessary.

Allow cancellation and handle interrupted renders safely.

Where practical, allow the user to retry a failed export without restarting the entire media-selection workflow.

## 7. Real video rendering and export

This is a critical requirement.

Implement an actual media-processing and video-encoding pipeline that produces a playable video file.

Evaluate appropriate technologies based on the existing project and deployment target. Possible options include:

* FFmpeg compiled to WebAssembly for browser-side media processing.
* WebCodecs for supported browser-native encoding workflows.
* A local desktop or server-side FFmpeg process if a browser-only solution cannot meet the requirements.

For a privacy-focused browser application, prefer local processing where technically feasible.

However, do not assume that a static-hosted website can freely execute native FFmpeg, that all browsers support identical codecs, or that WebAssembly can process arbitrarily large collections without memory constraints.

If using a static website, implement an architecture that works with the actual hosting restrictions. If reliable rendering requires a backend or desktop companion, explain that dependency and implement the most practical viable solution rather than simulating success.

Requirements:

* Produce a genuine downloadable video file.
* Prefer MP4 with H.264 video and AAC audio when supported by the selected encoding pipeline.
* Provide the promised output resolution when feasible.
* Preserve correct aspect ratios.
* Keep audio and video synchronized.
* Use suitable frame rates and encoding settings.
* Handle long-running jobs without freezing the interface.
* Release large temporary buffers and media resources when they are no longer needed.
* Display clear errors for unsupported codecs, insufficient memory, or failed encoding.
* Validate the finished file before presenting it as successful.
* Make the download action work on desktop and supported mobile browsers.

Never create a dummy MP4, rename an image to a video extension, return an empty file, or display a fake completion message.

## 8. Save and reuse artistic templates

Users must be able to save their preferred settings as reusable templates.

A template should contain:

* Template name.
* Target duration.
* Output quality.
* Artistic mood.
* Any supported optional preferences.
* Creation or modification information where useful.

Provide the ability to:

* Save the current configuration.
* Load a saved template.
* Rename a template.
* Duplicate a template.
* Delete a template after appropriate confirmation.
* Choose a default template.
* Export and import templates as JSON where practical.

Persist templates locally using an appropriate browser storage mechanism.

Do not save the actual photos, videos, or MP3 files inside a template. Save the creative configuration only.

Templates must remain available after refreshing or reopening the application, subject to the browser's storage rules.

Do not assume that a browser can retain unrestricted permission to the original media folder. Ask the user to reselect media when necessary.

Design templates so that the same creative settings can be reused with a completely different collection of media.

## 9. User interface and visual design

Create a premium, modern creative application, not a generic administration dashboard.

Use an elegant cinematic design language with:

* A refined dark interface.
* Strong visual hierarchy.
* Large, attractive media previews.
* Beautiful mood-selection cards.
* Subtle animations.
* Clean typography.
* Intuitive controls.
* Carefully designed progress states.
* Responsive desktop, tablet, and mobile layouts.
* Accessible labels, keyboard navigation, and readable contrast.

The main workflow should be immediately understandable:

**Select Media → Choose Duration, Quality and Mood → Preview → Generate → Download**

The primary action must always be obvious.

Avoid overwhelming the user with professional video-editing controls. The application is designed for ordinary people who want excellent results without learning video editing.

Use realistic empty states, loading states, success messages, and error handling.

Do not use decorative UI elements that look functional but do nothing.

## 10. Privacy, security, and reliability

Personal photographs and family videos are sensitive.

* Prefer local processing whenever feasible.
* Never upload user media without explicit disclosure and consent.
* Do not transmit filenames, photos, videos, or audio to analytics services.
* Do not embed personal media in remote logging or error reports.
* Revoke temporary object URLs when appropriate.
* Clean up temporary files and buffers.
* Handle permissions and browser storage limitations correctly.
* Protect against malformed media files and decoding errors.
* Avoid unnecessary third-party dependencies.
* Do not commit secrets, API keys, private media, or generated media to Git.
* Clearly disclose any external service required for rendering.

If any part of the implementation requires remote processing, explain exactly what data is transmitted and why.

## 11. Architecture and maintainability

Use the existing technology stack if it is appropriate.

Otherwise, choose a maintainable architecture with clearly separated modules for:

* Media selection and ingestion.
* Media metadata and thumbnails.
* Story and scene planning.
* Artistic mood presets.
* Timeline construction.
* Audio processing.
* Video rendering and encoding.
* Export validation.
* Template management.
* Application state and user interface.

Keep the story-planning logic separate from the rendering engine so that additional moods, effects, and export formats can be added later.

Avoid a monolithic implementation, duplicated logic, hardcoded assumptions, unnecessary dependencies, and excessive complexity.

Do not introduce an AI API merely to make the application appear intelligent. Implement the deterministic automatic storytelling engine first, using genuine media metadata and practical visual heuristics. Optional AI features may be added later if they offer real value.

Provide clear setup instructions, environment requirements, and a README explaining how to run, build, test, and deploy the application.

## 13. Implementation strategy

Implement the application in coherent, testable stages:

**Phase 1:** Project audit, technical design, and a polished responsive interface.

**Phase 2:** Real local media selection, metadata extraction, and preview gallery.

**Phase 3:** Automatic story planning, scene selection, timeline generation, and mood-specific effects.

**Phase 4:** Working media rendering, audio mixing, encoding, and downloadable exports.

**Phase 5:** Persistent templates, failure recovery, performance improvements, and privacy protections.

**Phase 6:** Automated tests, end-to-end export verification, documentation, and final audit.

Prioritize a complete, working end-to-end video-generation flow over implementing numerous superficial features.

If you must make a trade-off, clearly identify it and deliver a reliable vertical slice first. Do not silently substitute a mockup for a feature that is not implemented.
